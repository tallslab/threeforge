# Changelog

## 0.9.0 — 2026-09-16

### Upgrading from 0.8.0

The tables below list the changes that ask something of code, configuration or a stored expectation written against
0.8.0. Kinds: `API` (a signature, option or interface changed shape), `default` (a default changed), `rejected` (an
input, run or submission that passed now fails), `version` (a schema version gate), and `reported` (a value the
ledger, CLI, bench or tier detection reports differently for an unchanged scene). Each row summarises one or more
entries of [All changes](#all-changes), which also lists every fix that needs nothing from you.

#### Compiler (`World`, classify, bake, culling, instancing)

| Kind | Change | If you do nothing | What to do |

### All changes

- `lightingOf(lights, items, shadows)`'s third argument is now required. It defaulted to no shadow work, so a direct caller that omitted it reported 0 shadow texels and 0 casters whatever its lights were configured to do — a wrong number indistinguishable from a measured one. Breaking for direct callers only: `NO_SHADOW_WORK` is exported for a frame that really rendered no shadow map, `buildFrame` passes it for its own optional input, and no number the ledger reports moves.
- A failing pixel-parity verdict reason now names the worst view's changed-pixel count, e.g. `pixel parity 0.00% > 0% (3 changed pixels in the worst view)`. The reason rounds the percentage to two decimals, so at `--parity 0` a real failure read `pixel parity 0.00% > 0%` and looked like a passing run, with the counts only in the adjacent log line. A parity carrying no views keeps the old wording.
- `MaterialHashes`, the return type of the public `registry.hashesOf()`, is exported from the package entry point.
- The frame snapshot schema's `items[].material` gains `minimum: 0` and a description: a per-frame index of the submission's canonical material in first-draw order, shared by submissions that draw one material, not stable across frames.
- `threeforge schema`'s snapshot output describes `programHash` and `variantHash` as stable within a single run only, not across runs or processes, for materials with instance code, a prototype that is not one of three's own, or identity-keyed own data; a `variantHash` with a texture differs between runs too.
- `threeforge schema analyze|optimize`'s `compileReport` description calls out two fields worth reading in an otherwise open object: the bake summary's `keptCoincidentFaces` (coincident faces the seam guard kept) and `occlusion.skippedSynced` (batches given no occlusion proxy because they hold batch-synced movers).
- `pnpm bench`'s gate now fails when a gated metric is missing from the results or is not a finite number. Absent, `NaN`, `Infinity`, `null` and non-numeric values all read as "not worse" through the comparison, so a regression could hide as a hole in the results rather than as a worse number. `unattributed` is held to the same rule instead of being read as zero when it is absent or `NaN`. A metric the baseline does not carry yet is still skipped, so adding a metric is not itself a failure.
- The bench `programs` metric now counts the shaders the app compiled rather than the diagnostic's own. It pays for itself where the lossy default applies — Soldier −18.9 %, BrainStem −14.9 %, VirtualCity −9.5 %. `safe` is now the steps that are both pixel-exact and never cost bytes themselves; that is a claim about the steps, not a promise of a smaller file, since re-serializing the container can change the size on its own (the Fox grows 0.86 % before any step runs, the Buggy shrinks 27 %). - `optimize --parity 0` now means zero. `pass` was computed from the per-view percentage after rounding to three decimals, which at the harness's 1280x720 canvas reads `0.000` for anything up to 4 changed pixels of 921,600, so a run that moved pixels could report `pass: true` and exit 0. - A frame snapshot's `byReason[reason].top` names, and a hint's `message` and `objects`, are capped at 120 and 300 characters (`src/ledger/text.ts`): a single long or malicious node/material/light name can no longer balloon an `analyze`/`inspect`/`optimize` document or the hint it appears in.
- Every `page.evaluate` result the CLI reads (harness state, `compile()`, and `inspect`'s frame measurements) is cleaned before use, whether the call resolves or rejects: a resolved value goes through `sanitizeDeep` (ANSI escapes, control characters and bidi/zero-width formatting characters stripped; strings, arrays and non-finite numbers — `NaN`/`±Infinity`, replaced with `0` — capped/normalized; `src/cli/untrusted.ts`); a rejected one (a `window.__threeforge` hook that throws inside `compile()`/`frameAsync()`, or a predicate that throws) is cleaned the same way before it becomes a `PageError` — `inspect`'s target is any page, not only one using threeforge's own caps.
- CLI progress lines and the human summary (stderr with `--json`, stdout otherwise) are cleaned the same way, line by line; page errors keep only the first 5, each capped at 300 characters, with a `(+N more)` suffix for the rest. A failed command's own error text is now cleaned wherever it is printed or returned: `analyze`/`inspect`/`optimize`'s top-level stderr line and the MCP tools' `{ error, code }` JSON.
- A scene with several shadow-casting point lights or transmissive meshes now gets ONE `point-light-shadow`/`transmission` hint per code instead of one per light/mesh: the message states the count (e.g. `3 point lights render 6 shadow faces per frame: use spot lights or freeze their maps`) and `objects` holds the first 5 names. `sanitizeDeep`'s array cap no longer appends a `"(+N more)"` string marker to an array whose elements are not all strings (it would have made a typed array like `FrameSnapshot.hints` schema-invalid); such arrays are truncated silently instead.
- The MCP tools `analyze_asset`, `inspect_app` and `optimize_asset` now return a second `content` text block after the JSON, marking any name, hint text, `env.gpu` or verdict reason in it as data from the asset or page, not instructions; `explain_hint` is unchanged. The same paragraph is in AGENTS.md.
- An error result from `analyze_asset`, `inspect_app` or `optimize_asset` now carries a second `content` block too (`ERROR_NOTE`), marking the error text as data, never instructions: an error can quote the asset or page, such as an `extensionsRequired` name glTF-Transform repeats verbatim. `explain_hint`'s error, which quotes only the agent's own input, has none.
- Text the CLI and MCP read from an asset or page is now also cleaned of every Unicode format character (`\p{Cf}`, which includes the tag characters U+E0001 and U+E0020-E007F used to smuggle invisible instructions, U+061C, U+00AD and U+206A-206F), the rest of the tag block, variation selectors (U+FE00-FE0F, U+E0100-E01EF, Mongolian U+180B-180F) and invisible fillers (U+034F, U+115F, U+1160, U+3164, U+FFA0, U+17B4-17B5); U+2028 and U+2029 become a space.
- Each string the CLI and MCP read from a page is capped at 300 code points (the ledger's hint message cap), not 256, so a 257-300-character hint message keeps its tail.

- The bake's seam rule removes a coincident, opposite-winding pair only when the two islands come from different entries, every entry involved is a closed, manifold, outward shell (every edge used exactly once in each direction, every connected component with a positive signed volume), all draw front faces only (`side: FrontSide`), none casts shadows and all are opaque; every other pair (back-to-back sign cards, a floor lying on a ceiling, a pair inside one entry, back-side, double-sided, translucent or shadow-casting pairs, open or inside-out boxes, a shell joined to another part by a shared edge) is kept and counted in the new `keptCoincidentFaces` field of `BakeReport`, `BakeSummary` (`CompileReport.bake`) and the CLI bake lines, which counts only kept faces the bake does not remove otherwise (the CLI prints 0 for an older report without the field).
- Seam pairing only pairs islands that cover their region exactly once: an island with an edge used three or more times (whose outline could match a region of a different size) is not paired, and a pair where either island has overlapping triangles is kept. A doubled box beside a longer box used to lose the longer box's top where nothing covered it.
- Shadow-casting statics keep their seam and buried faces: non-VSM shadow maps draw a front-side material's back faces, so a removed seam face would change the shadow on the neighbouring module (visible with toon lighting). A rebake decides every removal again, counting a module as casting when its original or the baked mesh casts (`bakeEntriesOf` gains an optional seventh argument): once neither casts the next rebake may remove the seams, and turning `castShadow` on after compile keeps the faces only after the next rebake or recompile.
- Tinted groups (a BatchedMesh, InstancedMesh or baked mesh drawn with a white clone of the material) now render like their sources: the clone keeps every function assigned to the material instance (`onBeforeCompile`, `customProgramCacheKey`, `onBeforeRender`, a node material's `setup*`), custom `defines`, for node materials `alphaTest`, and by reference every other user-added own property (data a hook reads through `this`), which three's `clone()` dropped; it shares the source's `userData` object instead of three's JSON copy, so a uniform kept there and animated through the source reaches the batch, and circular or BigInt material `userData` no longer throws from `compile()` (new `cloneMaterial`).
- `BakeEntry` gains `opaque`, `side`, `castShadow` and `vertexColors`. `opaque` absent counts as not opaque, `side` absent as not front-side and `castShadow` absent as a shadow caster: that entry gets no seam, buried-face or duplicate removal. `opaque` is an allowlist of three's default material hooks: exactly one of three's 35 material classes (new `isBuiltInMaterial`; no subclass) with no function assigned to the instance (new `hasOwnFunctions`), no node in any slot, `onBeforeCompile` and `customProgramCacheKey` three's own, only three's material `defines`, no `displacementMap`, material `clippingPlanes`, `polygonOffset`, `wireframe` or `stencilWrite`, `depthFunc` `LessEqualDepth` (node-material statics authored with custom nodes keep all their faces). `vertexColors: false` ignores the geometry's colour attribute; absent keeps multiplying it by the tint. `bakeEntriesOf` sets them all from the material and each module (an optional fifth argument overrides `vertexColors`), and `BakedGroup.vertexColors` and `BakedGroup.opaque` record the original material's flags, so a rebake does not judge the group by its vertex-colour clone (whose `vertexColors` the bake turns on; `cloneMaterial` gives the clone the source's instance functions, `defines`, `alphaTest`, user-added own properties and shared `userData`). `bakeEntriesOf` gains an optional sixth argument, the opacity recorded at bake time.
- The buried-face pass removes only faces of opaque, front-side entries that cast no shadow (double-sided faces are no longer candidates), and counts only ray hits on the back side of an opaque front-side or double-sided face: a front-side card facing a face no longer buries it, and a face pressed against a neighbouring solid's front face is buried only when that solid's far side is within `distance`.
- Duplicate detection no longer deletes a region covered twice with different triangulations when another such region lies on the same plane: both fused islands had an empty outline and the second was taken for a copy of the first. Such regions now stay doubled. Exact copies are removed only between entries whose faces may be removed.
- The bake carries `tangent` when every entry has it (xyz turned by the entry's matrix and normalised, `w` unchanged even under a mirrored matrix, as three builds the bitangent as `cross(normalView, tangentView) * tangent.w`) and the weld compares it; tangents used to be dropped.
- `AnimatedInstances` draws part `k` of every character at the character matrix × `animation.parts[k].matrix`, a `mat4` uniform of that part's material read every frame: `setMatrixAt` folded `parts[0].matrix` into the instance matrix all parts share, so a prototype whose parts sit at different offsets from its root drew every part at the first part's offset. Prototypes whose parts all sit at the root (the Kenney mini characters of the crowd bench) draw as before.
- `AnimatedInstances.getMatrixAt(i)` returns the character matrix given to `setMatrixAt`; it returned that matrix × `animation.parts[0].matrix`.
