# Changelog

## Unreleased

- Material keys include material code by identity, not `toString()`: materials that differ only in an instance `setup*`, `onBeforeCompile` or `customProgramCacheKey` function, or in a class that is not one of three's own (a subclass keeps its base's `type`), no longer merge into one registry canonical or one batch drawn with the first material's code, even when the source text matches; they report as `shader-variant`s. An instance `onBeforeRender` keeps materials apart too, as a `uniform-variant` (same program). `clippingPlanes` key their count in the program and their values in the variant: materials with the same number of different planes merged. A user-added own property keys plain data by value (arrays and BigInts included) and any function, `Texture`, `Object3D` or class instance inside it by identity; a circular or BigInt one no longer throws in `register()` or `compile()`. A material's `dispose` listeners no longer change its key.
- `world.decompile()` disposes a batch or instanced material only when the World created it (a white clone for per-instance colour); a registered material the compiler shared because every instance was white was disposed too.
- New `world.dispose()`: decompiles when compiled (listeners hear `decompile`), removes the occlusion proxies and scene hooks, and drops every `onDirty` listener; a second call does nothing, and `compile`, `markDirty`, `setVisible`, `onDirty` and `warmup` then throw `World is disposed`.
- `world.bakeDebug()` returns copies of the removed faces; its meshes shared the group's geometry, which a rebake or `decompile()` disposed.
- Sprite batch materials take every field of the sprites' material through `material.copy()`, plus `alphaTest` by hand; the hand-written copy dropped `alphaMap`, `alphaHash`, `alphaToCoverage`, `vertexColors`, `depthFunc`, stencil, clipping planes, polygon offset, `colorWrite`, `blendColor`/alpha blend factors and `name`. `userData` is kept out of the copy (it stays empty), so a circular or BigInt `userData` cannot break `compile()`.
- `spriteRule` gains `sprite-node-material` (a node material with any `*Node` slot set) and `sprite-count` (`Sprite.count !== 1`): such sprites were batched, losing their node-driven position, scale or vertex output, shading object-dependent nodes against the batch, or drawing one instance instead of `count`.
- `spriteRule` gains `sprite-custom-material`: a sprite whose material's prototype is not exactly `SpriteMaterial.prototype` or `SpriteNodeMaterial.prototype` (a subclass overriding `setupPositionView`, `onBeforeCompile` or any other method), or which holds own function-valued properties (an instance `setup`, `onBeforeRender` …), was batched into a plain `SpriteNodeMaterial` that dropped that code.
- `world.warmup({ mode: 'frame' })` issued occlusion queries from proxies a depth-0 render parked earlier in the same task (their queued re-enable ran while `renderAsync` awaited `init()`); it now resumes them first and suspends them with the rest.
- `world.markDirty()` on a detached original clears `matrixWorldNeedsUpdate` after composing its world matrix, so an unforced `updateMatrixWorld()` on it (with `matrixAutoUpdate` off) keeps that matrix.

- `MaterialRegistry`'s colour key (`colorKey`, and every other `Color`-valued property folded into `variantKey`,
  such as `emissive`, `sheenColor` or the base `Material.blendColor`) is now keyed by exact linear floats
  (`color.r/g/b`) instead of 8-bit sRGB hex: two colours under 1/255 apart, and two HDR colours (a channel > 1)
  that would otherwise both clamp to the same hex, now stay distinct instead of silently merging and rendering
  with the first one's colour. `describe(material)` gains `colorKey` (the exact key; used for identity and
  grouping) alongside the existing `colorHex` (`color.getHexString()`, display only). Sprite batching
  (`groupSprites`, `src/compiler/sprites.ts`) groups by the exact `colorKey`, not `colorHex`. `variantKey` also
  gains `visible=0` when `material.visible` is false, so the registry never merges a hidden material with an
  otherwise-identical visible one (`programKey` is unaffected either way). Every material's `variantHash` changes
  as a result of this encoding change (every material carries `blendColor`, inherited from the base `Material`
  class); no `programHash` changes.
- `MaterialRegistry` caches a material's `programHash`/`variantHash` alongside its keys, so `describe()` no longer
  re-hashes on every call. `registry.invalidate(material)` re-keys a mutated material: it removes every index
  entry `register()` filed under its *old* keys (`canonicalByFullKey`, its program's `canonicals`/`variants`) before
  recomputing and re-filing it under its current properties' keys — without this removal step, a later, unrelated
  material matching the mutated material's old state would still merge into it and silently render with its new,
  mutated properties. `registry.forget(material)` removes a material from the registry entirely, as if it had never
  been registered; its doc comment now says plainly that this is not a signal it is safe to dispose the material's
  GPU resources, since materials merged into it as a canonical still resolve to that exact (now-forgotten) object.
  New `registry.dependentsOf(material)` counts how many other registered materials currently resolve to `material`
  as their canonical, so a caller can check it is `0` before disposing. A material is documented as immutable once
  registered: `docs/threeforge.md` section 5 and the `MaterialRegistry`/`materialKey.ts` doc comments spell out the
  contract and these three methods. None is wired into disposal yet (`World.decompile()` / `ResourceTracker` start
  calling `forget()`, checking `dependentsOf()` first, in a later phase).

- Compiled instance data is written in the scene's space (new `SceneSpace`, `src/compiler/space.ts`). Batch matrices, instanced masters, baked vertices, batch-sync matrices, `markDirty` writes and sprite centres and scales were world-space although every compiled object is a child of the scene, so a translated, rotated or scaled `Scene` applied its transform twice. The inverse of `scene.matrixWorld` is cached and derived again whenever the scene's world matrix changes, so a scene moved after compile is honoured; an untransformed scene copies world matrices unchanged. `BatchOptions`, `SpriteBatchOptions` and `SpriteFillOptions` gain an optional `space`, `bakeEntriesOf` an optional fourth `space` argument and `BakedGroup` a `space` field; `fillSpriteInstances` without `space` still writes world positions and scales, and `buildSpriteBatch` defaults to the space of `root`.
- `world.markDirty()` recomputes the bounds of each touched batch and instanced group once (every LOD level) and fits their occlusion proxies to them: an instance moved outside its old bounds was culled by three's whole-object frustum test while on screen, and its proxy kept the old size. `InstanceCullingHandle` gains `refreshBounds()`, which reads the master matrices rather than the compacted rows.
- `world.markDirty()` with `originals: 'detach'`: a detached original's own `matrixWorld` (from `updateMatrixWorld` with no parent) is its local matrix alone, so `markDirty` on it, or on a batched/instanced original nested under it, wrote the wrong instance transform whenever its former ancestors (the scene included) carried a transform — a regression for a direct child of a transformed scene, and a pre-existing bug for a nested one. `markDirty` now composes a detached original's world matrix from its recorded former parent's current `matrixWorld` instead. A second gap: `markDirty(ancestor)` never reached detached originals, since they are no longer its children; `World` now also reaches them, recursively, when a former parent (or an ancestor of it) is marked dirty.
- The batch sync rewrites every synced mover once the scene moved since its last sync (new `SceneSpace.version`), not only movers whose world matrix changed: a world-anchored mover (a physics body at rest, a floating-origin shift of the scene root) kept the old scene's matrix until it moved.
- `exclusionRule(mesh, root)` decides `mirrored` by the determinant relative to `root` (the world determinant times the root's) when `root` is given, and by the world determinant as before without it. three flips a batch's front face by its own world matrix, the scene's, never per instance: under a mirrored scene a mesh mirrored again was batched with inverted winding, and every other mesh stayed unbatched. A scene that becomes mirrored after compile is not handled.
- Sprite batches swap `FrontSide` and `BackSide` while their scene is mirrored, checked every render (new `SceneSpace.mirrored`): three flips a mesh's front face under a negative world determinant but never a sprite's, so a sprite batch under a mirrored scene culled every quad.
- Occlusion: in a render where the camera's eye is inside a proxy's box grown by twice `camera.near`, or its near-plane rectangle reaches into the box, the proxy issues no query and its targets are shown. From inside, every face is back-facing (and a front face in front of the near plane is clipped), so the query reported the batch around the camera as occluded, and that answer, read back two or more renders later, also hid the batch after the camera left.
- Occlusion proxies show or hide their targets only in the outermost render of the scene: a nested pass (a reflection, a portal) that drew a proxy used to set its targets from that pass's own query results.
- `occlusion: true` with `dynamics: 'batch-sync'`: a batch or instanced group holding a synced mover gets no occlusion proxy, so `report.occlusion.proxies` is lower, and the new `report.occlusion.skippedSynced` counts the targets skipped this way. The proxy kept its compile-time box, and a mover that left the box was hidden while on screen.
- `world.warmup()` (both modes) issues no occlusion query. Its 1×1-scissored frame counted no samples for every proxy, so once that answer was published, every target whose proxy was drawn vanished for at least one frame.
- Occlusion proxies drawn while their scene is rendered without its own hooks (as a child of another root) issue no query and show their targets. Before, the targets kept whatever visibility they last had.
- `freezableObjects` no longer freezes a container unless its subtree holds at least one static leaf (an unbatched
  static mesh or a hidden unsynced original): an empty container, an anchor `Object3D` with no children, and a
  light's `target` (for example `DayNight`'s `sun.target`, added straight to the scene) previously froze
  vacuously and never updated their matrix again. `village` (and any scene that adds a light's `target` to the
  scene) now reports one more `autoUpdatedMatrices` per such target.
- `classify`'s `exclusionRule(mesh, root?)` gains four rules the classifier previously missed: `invisible-ancestor`
  (an ancestor up to `root` with `visible = false` — a static mesh under a hidden Group no longer gets batched and
  drawn), `material-invisible` (`material.visible === false`, distinct from the mesh's own `visible`),
  `group-render-order` (the *nearest* `isGroup` ancestor has a non-zero `renderOrder`; three reassigns `groupOrder`
  at every Group on the way down, so a closer Group's `renderOrder` — 0 included — always wins over a farther one,
  and a non-Group `Object3D` in between is never read for this) and `clipping-group` (an enabled `isClippingGroup`
  ancestor at any depth — clipping contexts chain, so a farther enabled `ClippingGroup` still applies).
  `spriteRule(sprite, root?)` gains the last three. Both functions' new `root` parameter is optional; without it the
  ancestor-scoped rules are skipped, which is unchanged behaviour for existing callers.
- `nestedPasses: 'auto'` (the `World` default) now resolves to `'per-pass'` on both backends; it was `'reuse-main'` on WebGPU. `'reuse-main'` stays available as an explicit option, and the harness accepts `nested=reuse-main`.
- Compacted `InstancedMesh`es draw the right instances in shadow maps on both backends: a shadow pass keeps the rows the enclosing pass drew and appends, once per frame, the instances every shadow-casting light reaches (directional and spot frusta, a point light's cube of half-size `distance || shadow.camera.far`); `count` and `visibleIds` are restored when the nested render ends. On three's shared instance vertex buffer (more than 1,024 instances on WebGPU's default limit) an outermost compaction marks only the rows it changed with `addUpdateRange`, and a nested pass that writes rows marks the whole matrix and colour buffers: a receiver's instance frame event syncs before its shadow render, whose own sync would otherwise replace the main pass's ranges before they upload. A nested pass that reaches a mesh before the main pass compacts it for the main camera first, and reflections draw the main camera's list, under either policy. Shadow passes previously drew the main list under `reuse-main` (casters outside the view missing) and rewrote the main pass's list under `per-pass`. On WebGPU, shadow-pass `gpuDraws` and `triangles` rise where casters lie outside the view.
- `InstancingOptions.mainCamera` is replaced by `passes: PassTracker`; `createCulledInstancedMesh` without it compacts for every camera it is drawn with.
- `World.warmup({ mode: 'async' })` resets the pass tracker after `renderer.compileAsync()`, which calls the scene's `onBeforeRender` without `onAfterRender`; the warm-up frame and the next render were counted as nested passes.
- Compiled batches now draw the right instances in shadow maps and other nested passes (reflections, portals) on both backends: a nested pass keeps the index rows an open enclosing pass recorded as a stable prefix, zeroes the counts of those its camera does not need and appends the ids it lacks, and the counts are restored when the nested render ends. Under the WebGPU default `nestedPasses: 'reuse-main'` shadow maps previously lost every caster outside the main view; under `per-pass` the receiving batch that triggers the shadow render drew the shadow camera's list (on WebGPU every batch drawn before it did). The policy now only decides a batch no enclosing pass has culled yet (`per-pass`: a fresh cull; `reuse-main`: append to its last outermost rows). On WebGPU a nested pass issues one draw command per slot, zero-count slots included, so shadow-pass `gpuDraws` rise. `World` installs the new exported `PassTracker` scene hooks on every compile; `attachBvhCulling`'s `CullingOptions.mainCamera` is replaced by `passes: PassTracker`. Compacted `InstancedMesh`es get their own stable prefix (see the `InstancedMesh` bullet above).
- `World` gains a `transparent: 'batch' | 'keep'` option (default `'batch'`, unchanged). Three sorts a `BatchedMesh` back-to-front by its own bounding-sphere centre, not per instance, so transparent statics batched together composite in creation order relative to other transparent submissions instead of true per-object depth; `transparent: 'keep'` routes transparent statics aside as individual meshes instead (reported in `CompileReport.skipped` with rule `transparent-kept`, and in the ledger as reason `excluded:transparent-kept`). New info-severity hint `transparent-batch-order` (remedy in `npx threeforge explain transparent-batch-order`) fires when a threeforge transparent batch shares the main pass with another transparent submission; the harness exposes it as `transparent=keep`.
- dev scripts: `scripts/fetch-assets.mjs` and `scripts/fetch-kits.mjs` now confine every remote-derived filename (a `.gltf`'s `buffers`/`images` URIs, a Poly Haven API entry/include/single-file name) to its target directory with the new `scripts/fetch-safe.mjs`'s `safeLocalPath`, rejecting `..`, absolute paths, a URI scheme, NUL/backslash bytes, undecodable percent-encoding, and an existing symlinked ancestor that would redirect the write outside root — a compromised upstream response could previously write a file anywhere in the checkout (e.g. `../../../scripts/copy-decoders.mjs`). `fetch-kits.mjs` also lists a downloaded zip's entries with `unzip -Z1` and checks each through `safeLocalPath` before extracting (zip-slip), and replaces its shell `unzip -o -q "$zip" -d "$dir"` with `execFileSync('unzip', [...])`. Both scripts now guard their top-level downloads behind an entry-point check (`process.argv[1] === fileURLToPath(import.meta.url)`), so importing either module does no network or filesystem I/O. `test/assets/manifest.json`'s KhronosGroup URLs are pinned from `/main/` to the branch's current commit SHA at write time (`glTF-Sample-Models` → `d7a3cc8e51d7c573771ae77a57f16b0662a905c6`, `glTF-Sample-Assets` → `90d7ede14c7e280af263824604b427a1ca02cb66`); `mrdoob/three.js/r186` was already a tag and is unchanged.
- bench: `.github/workflows/bench-results.yml` no longer ingests a device result on every issue open/edit. It now ingests only after a repository collaborator with `write` or `admin` permission applies the `bench-accepted` label (checked live against the GitHub API for the user who applied it), and editing an issue that already carries `bench-accepted` removes the label and requires a maintainer to re-apply it before the (possibly changed) result is ingested. The workflow also drops top-level `permissions` to `{}` in favor of least-privilege per-job permissions, adds `timeout-minutes` to both jobs, scopes concurrency per issue instead of one shared group that cancelled pending runs, retries the commit-and-push up to 3 times against a moving `main` instead of failing outright, always comments the outcome (`if: always()`), and dispatches `pages.yml` after a successful push so the public device table actually updates. Neither the ingest script's exit status nor its message is passed through a fixed-delimiter `$GITHUB_OUTPUT` heredoc any more (closing an injection path where a crafted validation-error key name could forge a `status=0` output line).
- bench: the device bench page and its ingest pipeline are hardened against a submitted result carrying hostile data. `bench-app/table.ts`'s `esc` now escapes `'` (`&#39;`) as well as `&<>"`, and every value in a device row (`gpu`, `platform`, `backend`, `tier`, `createdAt`) is escaped, not just `gpu`/`platform` — a `createdAt` or `gpu` containing HTML no longer renders as markup on the public page.
- bench: `scripts/bench-schema.mjs`'s `validateDeviceResult` now rejects a `createdAt` that isn't a strict `YYYY-MM-DDTHH:mm:ss.sssZ` timestamp (previously anything `Date.parse`-accepted, including `<img src='2026-09-14`), and rejects a submitted `id` that doesn't match the id recomputed from that `createdAt`'s date and `env.gpu`/`env.ua`/`env.backend` (shared logic in the new `scripts/bench-id.mjs`, also used by `bench-app/submit.ts`) — a forged id can no longer misfile a result or spoof another device. `env.gpu`, `env.platform`, `env.ua` and `env.three` are now restricted to printable ASCII without `|`, a backtick, or a newline (verified against realistic values such as `ANGLE (Apple, ANGLE Metal Renderer: Apple M2, Unspecified Version)` and a full Chrome UA string; a GPU/platform string containing a non-ASCII `®`/`™` glyph would now be rejected).
- bench: `expandWire` (the wire-form expansion in `scripts/bench-schema.mjs`) now builds the expanded `scenes`/variant objects with `Object.create(null)`, and every own-key check in the schema now uses `Object.hasOwn` instead of `in`/`Object.keys().includes()`-only checks — a `__proto__` key in a submitted wire form used to be able to hijack the (then plain-`{}`) scenes object's own prototype, making a real scene (e.g. `zen`) silently read as present (via prototype inheritance) with none of its metrics ever validated; it's now reported as a missing scene, and the real `Object.prototype` is never touched.
- bench: `scripts/bench-ingest.mjs`'s `extractJson` scans the issue body for a ` ```json ` fence with a linear `indexOf` scan instead of a backtracking regex (a 2,000-line whitespace-only body used to block for several seconds; it now returns in under a millisecond) and throws if the body exceeds 65,536 characters. `ingest` writes the result file with `flag: 'wx'`, so a second submission for an id that already exists throws instead of silently overwriting the first.
- bench: `scripts/bench-devices.mjs`'s `readResults` now validates every file it reads and throws, naming the file, if one fails; `renderDevices` now backslash-escapes `|` and collapses newlines in every Markdown table cell, so a hostile GPU/platform string can no longer break out of its cell or add a spurious table row.
- bench: the bench page's footer link to the source repository is now built from `VITE_FORGE_REPO` (matching the submit-issue link) instead of a hard-coded `github.com/threeforge`, and is hidden when the variable isn't set at build time.
- bench: `bench-app/runner.ts` now normalizes `env.gpu`/`platform`/`ua`/`three` (new `normalizeEnvString` in `bench-app/submit.ts`) before hashing the id and building the issue body, so real driver/browser strings that carry `®`/`™`/`©` or accented letters (WebGPU `adapter.info` and `UNMASKED_RENDERER_WEBGL` routinely report `NVIDIA® GeForce RTX™ 4080`) are no longer rejected at ingest: `®`→`(R)`, `™`→`(TM)`, `©`→`(C)`, accents are stripped to their ASCII base (`é`→`e`), and anything else outside the schema's printable-ASCII charset becomes `?` (a control character becomes a space). The schema's charset itself is unchanged.

- docs: `exposeToAgents(...)` is now shown guarded (`if (import.meta.env.DEV) exposeToAgents(...)`) in `docs/threeforge.md` and the generated agent docs (`AGENTS.md`, `docs/agents.md`), with a sentence noting the hook lets any script on the page call `compile()`/`decompile()` and read the ledger, so it should ship only in development builds or behind your own flag. No code change to `src/agent/expose.ts`.
- `optimize` exits 2, before glTF-Transform reads anything, when an `images[].uri` or `buffers[].uri` of the input (a `.gltf`, or a `.glb`'s JSON chunk) is absolute, has a scheme other than `data:` (`file:`, `http:`, `C:`), contains a backslash or NUL, is not valid percent-encoding, or resolves outside the input's directory, also by real path through a symlink. glTF-Transform resolved these unconfined, so a hostile `../../.ssh/id_ed25519` was embedded into `<name>.forge.glb`. A `.gltf` output whose resource URIs would leave its directory (resources are named after `--out`, so `..%2F..%2Fx.gltf` wrote `../../x.bin`) also exits 2 before anything is written.
- `optimize --out` must end in `.glb` or `.gltf` (exit 2; `--out x.txt` used to write glTF JSON) and must not be the input file compared by device and inode, so a hard link, a symlink or a case variant on a case-insensitive filesystem no longer overwrites the input (exit 2). A `.glb` output in any case (`.GLB`) is written as binary glTF; it used to be written as JSON with side files. `--out` also must not be one of a `.gltf` input's own resources, and a `.gltf` output whose resource would land on the input or on one of its resources (same path, or same device and inode) exits 2 before anything is written: glTF-Transform keeps each resource's URI, so `optimize scene.gltf --out scene.opt.gltf` rewrote `scene.bin` beside the input, left `scene.gltf` unloadable and exited 0. Write a `.gltf` output to another directory, or as `.glb`.
- A page error raised by the harness page now fails the `analyze` verdict and, in either verified render, the `optimize` verdict (exit 1), with one reason quoting up to five errors cleaned and capped (`1 page error: …`; the original render's starts `the original file raised`). `inspect` still only logs page errors. `verdictOf` takes an optional fifth `pageErrors` argument, `analyzeAssetWithShots` also returns `pageErrors`, and the MCP data note (and AGENTS.md) says verdict reasons can quote page errors.
- `optimize`'s `requires[]` code for `KHR_texture_basisu` now reads `await renderer.init(); ktx2.detectSupport(renderer);` instead of `detectSupportAsync`, deprecated since three r181.

- `measureViaHook(page, frames, timeout)` gained a `timeout` parameter (default 60000 ms, matching `--timeout`); it previously ran the whole N-frame measurement unbounded.
- The MCP server (`threeforge mcp`): `inspect_app`'s input schema no longer has a `tier` field (the CLI already refuses `inspect --tier`; the handler now always measures at `tier: 'auto'`).
- Every numeric bound and choice (`frames` ≥ 1 and an integer, `backend`/`tier`/`bake`/`preset`/`compress`/`textures` one of their listed values, `inspect_app`'s tier, `optimize_asset`'s budget/verify pairing, and so on) is now checked once by the same `validateInput`/`CHOICES`/`RANGES` the CLI uses, so a bad value always returns the same `{ error, code: 2 }` JSON — previously a tight `z.enum(...)` or `.int()` in the MCP input schema made some fields (an unknown `backend`, a fractional `frames`) return the SDK's own plain-text schema error instead, while others (`frames: 0`, an out-of-range `timeout`) already returned threeforge's JSON. The allowed values of each field stay discoverable to agents through its `.describe()` text instead of a JSON Schema `enum`.
- `optimize_asset.out` must end in `.glb` or `.gltf` and sit inside the input file's directory or the working directory, and a new `overwrite` input (default `false`) is required to replace a file that already exists — both return `{ error, code: 2 }` (the existing-file case matches `/exists/`). The directory check now canonicalises both the allowed roots and the target's nearest existing ancestor with `realpathSync` before comparing (matching the static server's existing defense, `src/cli/server.ts`), so a symlink under either root that leads outside it is refused even though it looks lexically contained; and the filesystem root is never treated as an allowed working directory (every path is trivially "inside" `/`), so a server started at `cwd === '/'` can no longer be tricked into accepting an `out` anywhere on disk just by giving it a `.glb`/`.gltf` name.
- `optimize`'s `overwrite` rule (Ruling R21) now also protects a `.gltf` output's resource files (`.bin`, textures), not only the `out` path itself: `optimizeAsset` takes a new `overwrite` input (`OptimizeInput.overwrite`, optional, default `true` — the CLI keeps replacing outputs unchanged), and when `false` it exits 2 before writing anything if `out` or any resource target it is about to write (resource names derive from the `out` basename, e.g. a lone buffer becomes `<basename>.bin`) already exists, naming the clashing path. `optimize_asset`'s existing `overwrite` argument (default `false`) is now passed through to this check, so `overwrite: false` also refuses an unrelated pre-existing file that happens to share a resource's name, which `resolveOptimizeOut`'s existing `out`-only check did not catch.
- `timeout`'s description now says it bounds each page step (load, every evaluate, the N-frame measurement, `compile()`), not just "the page".
- Every MCP tool carries `readOnlyHint`/`destructiveHint`/`openWorldHint` annotations (`optimize_asset` is the only one marked destructive; `inspect_app` the only one marked open-world).
- Closing stdin (the client disconnecting) now closes the MCP connection and lets the server process exit, instead of leaving it running forever: the SDK 1.30 stdio transport only listens for `data`/`error` on stdin, never `end`. A tool call still running when the client disconnects is now aborted too — `analyzeAsset`/`inspectApp`/`optimizeAsset` accept a `signal` (`CliDeps`, `src/cli/lifecycle.ts`) that closes the call's own browser/static server and lets it reject promptly instead of running to completion after nothing will read the result; the CLI's own behaviour is unchanged when no signal is given.
- `analyze`'s harness page now disposes its PMREM environment generator, `RoomEnvironment` and Draco/KTX2 loaders after use; every `analyze` document previously carried a false `unreferenced-resources` hint (13 geometries, 4 textures) even for a single skinned mesh like the Fox.
- `analyze` and `optimize` now exit 3 promptly when Chromium cannot launch; before, the exit-3 message printed and the process never exited because the static server stayed open.
- `analyze`, `inspect` and `optimize` bound every `page.evaluate` by `--timeout` and exit 4 with `page: <step> timed out after <ms> ms`; a hook whose `frameAsync` never settled used to hang past `--timeout`.
- The CLI closes its static server and browser on every path, newest first, each close bounded to 5 s; the first error is reported. A finished command (all but `mcp`) exits at most 5 s after flushing its output even if a handle lingers.
- `window.__threeforge.frameAsync()` rejects when the render throws; it used to stay pending forever.
- Programmatic `analyzeAsset`, `analyzeAssetWithShots`, `inspectApp` and `optimizeAsset` take an optional trailing `deps` (`{ launch, serve, appDir, signal }`, type `CliDeps`); `Resources.armAbort(signal)` (`src/cli/lifecycle.ts`) closes a call's resources when `signal` aborts.
- The static server (`analyze`'s harness/asset host) no longer crashes the process on a malformed request URL, such as a texture named `100%.jpg`: a request whose path fails to decode now falls back to the literal, undecoded path when it names a real file inside the root, and answers 400 otherwise. It also compares real paths (`realpathSync`), so a symlink inside the root that resolves outside it now answers 403 instead of being served, and any other unexpected error in a request answers 500 instead of taking the server down.
- The CLI parser is declarative (`COMMAND_SPECS` in `src/cli/args.ts`). Boolean flags no longer swallow the next argument (`analyze --json scene.glb`, `inspect --compile <url>` and `optimize --simplify scene.glb` now parse), `--` ends the flags, and the usage text plus the AGENTS.md command and flag tables are generated from the specs.
- `RANGES` and `validateInput(command, input)` in `src/cli/args.ts` hold the input bounds and cross-field rules for the CLI (and the MCP server next).
- `inspect` still compiles by default; the docs now show `[--no-compile]` instead of an opt-in `[--compile]` (still accepted). `--timeout`, `--headed`, `--simplify-error`, `--texture-quality` and `decoders` are documented.
- With `--json`, the document is written to stdout before the human summary is built, so a summary that throws no longer loses the JSON.
- Inputs that now exit 2 (usage error, nothing on stdout):

|---|---|---|

| a flag of another command (`inspect <url> --tier desktop`, `inspect <url> --bake`, `decoders <dir> --json`) | ignored | exit 2, naming the commands that take it |
| `--no-<flag>` of a flag without a negation (`--no-json`) | ignored | exit 2 |
| single-dash flag (`analyze a.glb -json`) | taken as a positional, then ignored | exit 2 with the `--json` suggestion |
| a flag before the command (`threeforge --frames 5 analyze a.glb`) | parsed | exit 2 |

- A frame snapshot's `byReason[reason].top` names, and a hint's `message` and `objects`, are capped at 120 and 300 characters (`src/ledger/text.ts`): a single long or malicious node/material/light name can no longer balloon an `analyze`/`inspect`/`optimize` document or the hint it appears in.
- Every `page.evaluate` result the CLI reads (harness state, `compile()`, and `inspect`'s frame measurements) is cleaned before use, whether the call resolves or rejects: a resolved value goes through `sanitizeDeep` (ANSI escapes, control characters and bidi/zero-width formatting characters stripped; strings, arrays and non-finite numbers — `NaN`/`±Infinity`, replaced with `0` — capped/normalized; `src/cli/untrusted.ts`); a rejected one (a `window.__threeforge` hook that throws inside `compile()`/`frameAsync()`, or a predicate that throws) is cleaned the same way before it becomes a `PageError` — `inspect`'s target is any page, not only one using threeforge's own caps.
- CLI progress lines and the human summary (stderr with `--json`, stdout otherwise) are cleaned the same way, line by line; page errors keep only the first 5, each capped at 300 characters, with a `(+N more)` suffix for the rest. A failed command's own error text is now cleaned wherever it is printed or returned: `analyze`/`inspect`/`optimize`'s top-level stderr line and the MCP tools' `{ error, code }` JSON.
- A scene with several shadow-casting point lights or transmissive meshes now gets ONE `point-light-shadow`/`transmission` hint per code instead of one per light/mesh: the message states the count (e.g. `3 point lights render 6 shadow faces per frame: use spot lights or freeze their maps`) and `objects` holds the first 5 names. `sanitizeDeep`'s array cap no longer appends a `"(+N more)"` string marker to an array whose elements are not all strings (it would have made a typed array like `FrameSnapshot.hints` schema-invalid); such arrays are truncated silently instead.
- The MCP tools `analyze_asset`, `inspect_app` and `optimize_asset` now return a second `content` text block after the JSON, marking any name, hint text, `env.gpu` or verdict reason in it as data from the asset or page, not instructions; `explain_hint` is unchanged. The same paragraph is in AGENTS.md.

- The bake's seam rule removes a coincident, opposite-winding pair only when the two islands come from different entries, every entry involved is a closed, manifold, outward shell (every edge used exactly once in each direction, every connected component with a positive signed volume), all draw front faces only (`side: FrontSide`), none casts shadows and all are opaque; every other pair (back-to-back sign cards, a floor lying on a ceiling, a pair inside one entry, back-side, double-sided, translucent or shadow-casting pairs, open or inside-out boxes, a shell joined to another part by a shared edge) is kept and counted in the new `keptCoincidentFaces` field of `BakeReport`, `BakeSummary` (`CompileReport.bake`) and the CLI bake lines, which counts only kept faces the bake does not remove otherwise (the CLI prints 0 for an older report without the field).
- Seam pairing only pairs islands that cover their region exactly once: an island with an edge used three or more times (whose outline could match a region of a different size) is not paired, and a pair where either island has overlapping triangles is kept. A doubled box beside a longer box used to lose the longer box's top where nothing covered it.
- Shadow-casting statics keep their seam and buried faces: non-VSM shadow maps draw a front-side material's back faces, so a removed seam face would change the shadow on the neighbouring module (visible with toon lighting). A rebake decides every removal again, counting a module as casting when its original or the baked mesh casts (`bakeEntriesOf` gains an optional seventh argument): once neither casts the next rebake may remove the seams, and turning `castShadow` on after compile keeps the faces only after the next rebake or recompile.
- Tinted groups (a BatchedMesh, InstancedMesh or baked mesh drawn with a white clone of the material) now render like their sources: the clone keeps every function assigned to the material instance (`onBeforeCompile`, `customProgramCacheKey`, `onBeforeRender`, a node material's `setup*`), custom `defines`, for node materials `alphaTest`, and by reference every other user-added own property (data a hook reads through `this`), which three's `clone()` dropped; it shares the source's `userData` object instead of three's JSON copy, so a uniform kept there and animated through the source reaches the batch, and circular or BigInt material `userData` no longer throws from `compile()` (new `cloneMaterial`).
- `BakeEntry` gains `opaque`, `side`, `castShadow` and `vertexColors`. `opaque` absent counts as not opaque, `side` absent as not front-side and `castShadow` absent as a shadow caster: that entry gets no seam, buried-face or duplicate removal. `opaque` is an allowlist of three's default material hooks: exactly one of three's 35 material classes (new `isBuiltInMaterial`; no subclass) with no function assigned to the instance (new `hasOwnFunctions`), no node in any slot, `onBeforeCompile` and `customProgramCacheKey` three's own, only three's material `defines`, no `displacementMap`, material `clippingPlanes`, `polygonOffset`, `wireframe` or `stencilWrite`, `depthFunc` `LessEqualDepth` (node-material statics authored with custom nodes keep all their faces). `vertexColors: false` ignores the geometry's colour attribute; absent keeps multiplying it by the tint. `bakeEntriesOf` sets them all from the material and each module (an optional fifth argument overrides `vertexColors`), and `BakedGroup.vertexColors` and `BakedGroup.opaque` record the original material's flags, so a rebake does not judge the group by its vertex-colour clone (whose `vertexColors` the bake turns on; `cloneMaterial` gives the clone the source's instance functions, `defines`, `alphaTest`, user-added own properties and shared `userData`). `bakeEntriesOf` gains an optional sixth argument, the opacity recorded at bake time.
- The buried-face pass removes only faces of opaque, front-side entries that cast no shadow (double-sided faces are no longer candidates), and counts only ray hits on the back side of an opaque front-side or double-sided face: a front-side card facing a face no longer buries it, and a face pressed against a neighbouring solid's front face is buried only when that solid's far side is within `distance`.
- Duplicate detection no longer deletes a region covered twice with different triangulations when another such region lies on the same plane: both fused islands had an empty outline and the second was taken for a copy of the first. Such regions now stay doubled. Exact copies are removed only between entries whose faces may be removed.
- The bake carries `tangent` when every entry has it (xyz turned by the entry's matrix and normalised, `w` unchanged even under a mirrored matrix, as three builds the bitangent as `cross(normalView, tangentView) * tangent.w`) and the weld compares it; tangents used to be dropped.
