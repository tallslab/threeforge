# Changelog

## 0.9.0 (2026-09-16)

### Upgrading from 0.8.0

Each row is a change that can ask something of code, configuration or a stored document written against 0.8.0. Kinds: `API` (an export changed shape), `default` (a default changed), `rejected` (an input that passed now fails), `version` (a schema gate) and `reported` (a value the ledger or registry reports differently for an unchanged scene).

| Kind | Change | If you do nothing | What to do |
|---|---|---|---|
| default | `nestedPasses: 'auto'`, the `World` default, resolves to `'per-pass'` on both backends; it was `'reuse-main'` on WebGPU. | Shadow maps and other nested passes cull for their own camera, so casters outside the main view are drawn. | Pass `nestedPasses: 'reuse-main'` to keep the old policy. |
| API | `CullingOptions.mainCamera` (`attachBvhCulling`) and `InstancingOptions.mainCamera` (`createCulledInstancedMesh`) are replaced by `passes: PassTracker`. | `mainCamera` no longer type-checks; without `passes` every render culls for its own camera, which is wrong inside a shadow map or a reflection. | Create a `PassTracker`, `install(scene)` it and pass it as `passes`. `World` does this on every compile. |
| API | New `World` option `transparent: 'batch' \| 'keep'`, default `'batch'`. | Transparent statics stay batched and composite in creation order relative to other transparent submissions. | Pass `'keep'` where per-object depth order matters. |
| API | `exclusionRule(mesh, root?)`, `spriteRule(sprite, root?)` and `groupSprites(…, root?)` take the compile root; `SpriteKeys.colorHex` is replaced by `colorKey`. | Direct callers skip the ancestor rules (`invisible-ancestor`, `group-render-order`, `clipping-group`) and judge `mirrored` in world space; a `describe` returning `colorHex` no longer type-checks, and in plain JavaScript sprites of one variant in different colours batch in the first sprite's colour. | Pass the root the objects are compiled under, and return `registry.describe(material).colorKey`. |
| API | `BakeEntry` gains `opaque`, `side`, `castShadow` and `vertexColors`. | A hand-built entry without them gets no seam, buried-face or duplicate removal. | Set the four fields from each mesh and its material. |
| API | `SpriteBatch.dispose()` takes an optional `{ material }`. | A plain `dispose()` still disposes the batch material. | Pass `{ material: false }` to keep a material that is still in use. |
| API | `AnimatedInstances.getMatrixAt(i)` returns the matrix given to `setMatrixAt`; it returned that matrix × `animation.parts[0].matrix`. | Code that compensated for the first part's offset now over-corrects. | Remove the compensation. |
| API | `DayNight.setTime()` rewrites the dome's vertex colours only when the palette changed; new `refreshDome()`. | Colours you wrote to `dome`, or a swapped dome geometry, are no longer overwritten within an unchanged palette. | Call `refreshDome()` before `setTime()` when it should rewrite them. |
| API | `RenderScheduler` updates the camera's and each watched object's world matrix before comparing them. | A watched detached original (`originals: 'detach'`) has its composed world matrix reset every tick. | Do not `watch()` a detached original. |
| API | A registered material is immutable: keys and hashes are cached. New `registry.invalidate(material)`, `forget(material)`, `dependentsOf(material)` and `hashesOf(material)`. | A material mutated after `register()` keeps describing, hashing and merging by its old properties. | Call `registry.invalidate(material)` after mutating a registered material. |
| reported | Material keys use material code by identity, not `toString()`, and colour keys use exact linear floats instead of 8-bit hex. | Every `variantHash` changes; hashes of materials with instance functions, subclasses, textures or identity-keyed own data are stable within one run only; materials differing only in such code, or in colours under 1/255 apart, no longer merge, so `sceneSubmissions` can rise. | Do not store or compare those hashes across runs. |
| version | The frame snapshot is `schemaVersion: 3` (`ledger.frame()`, `window.__threeforge.schemaVersion`, `threeforge schema snapshot` with `$id` `frame-snapshot-v3.json`), with new required fields `items[].material`, `memory.measured` and `js.ledgerMs`. | A validator built from the 0.8.0 schema rejects the new fields; a hand-built `SubmissionRecord`, `MemorySnapshot` or `JsSnapshot` no longer type-checks. | Validate against `threeforge schema snapshot`; set the new fields. |
| API | `lightingOf(lights, items, shadows)` requires its third argument. | A direct call without it no longer type-checks. | Pass the frame's `ShadowWork`, or the exported `NO_SHADOW_WORK`. |
| API | `estimateMemory(scene, info, viewport, options?)` gains `renderTargets`, `internalTextures`, `shadowMapType`, `rendererTextures`, `internalGeometries` and `frameBufferTargets`. | A direct call without them reports three's own PMREM, `DFG_LUT`, shadow-map and frame-buffer resources as unreferenced. | Pass them, or read the ledger's `memory.unreferenced`, which does. |
| API | `HintContext` gains optional `objects` (`MainPassObjects`), `unsupportedObjects` and `localSpaceDraws`. | `hintsFor` falls back to submission counts, so its object-counting hints read higher than the ledger's. | Pass them when calling `hintsFor` directly. |
| API | `OverdrawRenderer` requires `renderObject` and the accessors `measureOverdraw()` restores; `LedgerRenderer` and `WarmupRenderer` drop `renderAsync`. | Nothing for a three.js renderer; a hand-written stand-in no longer type-checks. | Give a stand-in the new members. |
| reported | New reason `static-unbatched`: a static drawn alone whose material another main-pass object also draws. `unique-material` now means no other object draws it. | `byReason['unique-material']` shrinks, and `static-unbatched` holds what it lost. | Read both reasons. |
| reported | Shadow-casting lights that share a name get pass ids `shadow:<name>#k`; repeated `nested:` and `scene:` ids get `#2`, `#3`; VSM blur quads move to `shadow:<id>:vsm` as `renderer-internal`. | Lookups by pass id miss; `sceneSubmissions` drops by 2 per non-point VSM map render. | Match pass ids by prefix, or name lights, targets and scenes distinctly. |
| API | `detectTier` is GPU-first; `TierInput` gains `mobile` and `platform`; new `tierInputFromNavigator(gpu, nav)`. | A hand-built input can give a touch-capable desktop GPU, or a Windows-on-ARM laptop under WebGPU, a phone tier and its budgets. | Build the input with `tierInputFromNavigator`. |
| rejected | The CLI parser rejects unknown flags, flags of another command, values on boolean flags, repeated flags, flags before the command, extra positionals, malformed or out-of-range numbers, and `optimize --budget` with `--no-verify`. | Those invocations exit 2 with nothing on stdout, where 0.8.0 ignored, clamped or rounded them. | Fix the invocation; the message names the problem. |
| rejected | `analyze` and `optimize` refuse an `images[].uri` or `buffers[].uri` that is absolute, has a scheme other than `data:`, or resolves outside the input's directory (by real path too); a file that is not readable glTF exits 2, not 4. | Such inputs exit 2 before a browser opens, where 0.8.0 fetched or embedded the resolved files. | Keep every resource inside the asset's directory, or embed it as `data:`. |
| rejected | `optimize --out` must end in `.glb` or `.gltf` and must not be the input or one of its resources; a `.gltf` output's resources must not land on them either. | `optimize scene.gltf --out scene.opt.gltf` exits 2 instead of rewriting `scene.bin`. | Write a `.gltf` output to another directory, or as `.glb`. |
| default | `optimize --preset safe` runs dedup, palette and prune; `weld` and `resample` move to `balanced` and `aggressive`. | `safe` outputs lose weld's and resample's savings. | Add `--weld` or `--resample`, or use `balanced`. |
| rejected | `--parity 0` is judged on every view's raw `changedPixels` (a pixel whose R, G or B moved by more than 24), and two renders of different sizes count as every pixel changed. `analyze` gains `--parity <pct>` (MCP `parity`), default 0.5, with the same rule. | An `optimize --parity 0` run that moved up to 4 of 921,600 pixels and passed now fails. | Pass a non-zero `--parity` to allow a small change; run `analyze --parity 0` before trusting `--bake`. |
| rejected | A page error raised by the harness page fails the `analyze` verdict and, in either verified render, the `optimize` verdict. | Such runs exit 1 with a reason quoting up to five errors; `inspect` still only logs them. | Fix what the asset raises in the page. |
| default | Every page wait of `analyze`, `inspect` and `optimize` is bounded by `--timeout`, screenshots and `browser.newPage()` included. | A step longer than `--timeout` exits 4 with `page: <step> timed out after <ms> ms` instead of hanging. | Raise `--timeout` for slow pages. |
| version | The `analyze`, `inspect` and `optimize` documents are `schemaVersion: 2` (`$id` `https://threeforge.dev/schema/<command>-v2.json`): `parity.views[].changedPixels`, `analyze`'s `input.parity`, `compile.skippedCount` and `groupCount`, `optimize`'s optional `input.overwrite`; every fixed-shape object is closed. | A 0.8.0 consumer rejects a 0.9.0 document, and a 0.9.0 consumer rejects a stored 0.8.0 one. | Validate against `threeforge schema <command>`, and re-run stored documents. |
| version | `threeforge inspect`, MCP `inspect_app` and `analyze`'s in-page check require a hook publishing `schemaVersion: 3`, and the returned frame must carry it too. | Against an app on threeforge 0.8.0 they exit 4 with `unsupported schemaVersion 2`. | Upgrade threeforge in the app. |
| API | `threeforge/cli`: `analyzeAsset`, `analyzeAssetWithShots`, `inspectApp` and `optimizeAsset` take an optional trailing `deps` (`CliDeps`); `verdictOf` an optional fifth `pageErrors`; `OptimizeInput` gains `overwrite` (default `true`); `measureViaHook(page, frames, timeout)` gains `timeout` (default 60000 ms). | Existing calls type-check; `measureViaHook` gives up after 60 s. | Pass `deps.signal` to abort a call, `pageErrors` to `verdictOf` to judge them, and a larger `timeout` for slow pages. |
| API | The MCP `inspect_app` tool has no `tier` input; every input is checked by the CLI's rules and a bad value returns `{ error, code: 2 }` instead of the SDK's schema error; `analyze_asset`, `inspect_app` and `optimize_asset` results and errors carry a second `content` block marking the text as data. | A client passing `tier`, parsing every content block as JSON, or matching the SDK's error text breaks. | Drop `tier`, parse the first block only, handle `code: 2`. |
| rejected | The MCP `optimize_asset.out` input must end in `.glb` or `.gltf`, lie by real path inside the input's or the working directory, and not be a symlink; new `overwrite` input, default `false`, also guards a `.gltf` output's resource files. | An `out` elsewhere, or onto an existing file, returns `{ error, code: 2 }`. | Choose `out` inside those directories, and pass `overwrite: true` to replace a file. |

### Known limitations

The limitations that remain (occlusion proxies hiding a group from shadow and reflection passes, a `compile()` that throws mid-way, materials that read mesh-local space once batched, seam removal with the camera inside a module, gaps in `memory.unreferenced`, WebGPU pixel checks in CI) are listed under "Known limitations of 0.9.0" in section 14 of `docs/threeforge.md`.

### All changes

#### Ledger

- Measured overdraw counts every fragment as exactly 1 whatever its colour, ignores the background, and draws each object with its own `side`, `map`, `opacity`, `alphaHash` and alpha nodes; sprites and sprite batches count their billboards. Batched scenes stop under-counting (the Buggy read 1.26 before batching and 0.52 after) and opaque counts of closed geometry roughly halve. `measureOverdraw()` restores every renderer setting it changes, can be called from a render hook, and keeps its target per renderer (`disposeOverdraw`, called by `detach()`).
- `lighting.lights` and `shadowLights` count the lights three projected for the main pass; `shadowTexels` counts only the maps rendered this frame, a point light at `mapSize.width² · 6` (the same rule `ShadowBudget` follows); `shadowCasters` counts distinct objects drawn into any shadow map, not display names.
- `memory.textures.bytes` follows three r186's sizing (channels from the format, bytes from the type, layers, video frames, mip levels); `memory.renderTargets` counts only the shadow maps three has built plus two VSM blur targets per non-point map; `memory.unreferenced` no longer counts what three holds for itself (PMREM planes and targets, the background sphere, morph textures, draw-once render targets, the `DFG_LUT`, the frame buffer). The standard `scene.environment = hdr` setup reported 10 geometries and 16 textures with the hint firing, now 0 and 0. New `memory.measured` carries three's own `renderer.info.memory` counts and bytes.
- The `untagged`, `unique-materials`, `static-unbatched`, `sprites-unbatched` and `unsupported-material` hints count distinct objects, not submissions across every pass (11 casters under one sun no longer read as 22 meshes); `point-light-shadow` and `transmission` fire once per scene with a count and name only what three renders. New hints `static-unbatched` (more than 20 such submissions), `transparent-batch-order` (info) and `batch-local-space` (warn: a compiled draw whose material has a node in any slot, `alphaHash`, an object-space normal map or custom material code, which three shades in the batch's space). `verdictOf` fails on `error` alone, so no CLI verdict changes.
- New `js.ledgerMs`, the time the ledger spends filing a frame (shown as `ms ledger`, reported by `analyze` and `inspect` as a median); `js.renderMs` no longer includes it.
- Expected GPU draws follow the side three draws in each pass (`shadowSide` in a shadow pass, the override's under a scene override); a mesh over an empty `InstancedBufferGeometry` or a vertex range three rejects predicts 0 draws, so `totals.unattributed` no longer goes negative; a `BatchedMesh`'s `instancesDrawn` and `drawCommands` count only slots with a non-zero index count.
- A frame rendered through `renderer.renderAsync()` reports a `main` pass with its shadow passes; `ledger.attach()` after a `detach()` from inside a draw no longer throws; names in `byReason[].top` and a hint's `objects` are capped at 120 characters, messages at 300.
- The ledger's own cost at 10k submissions fell from 1.84 to 0.30 µs per submission and from 11.4 MB to 17 KB allocated per frame (`node scripts/ledger-overhead.mjs`), a constant that no longer grows with the submission count; no snapshot number changes.
- `detectTier` decides by a recognised GPU before touch, with word-bounded names: a touch-capable desktop GPU is `desktop`, non-SGX PowerVR is `phone-mid`, a Windows-on-ARM laptop is `desktop` on both backends, and an M-series iPad with a touchscreen is `phone-mid`.
- `MainPassObjects`, `HintItem`, `NO_SHADOW_WORK`, `MaterialHashes`, `SpriteBatchDisposeOptions` and `tierInputFromNavigator` are exported from the package entry point.

#### Compiler and bake

- Compiled batches and compacted `InstancedMesh`es draw the right instances in shadow maps, reflections and portals on both backends: a nested pass keeps the rows the enclosing pass drew and appends what its own camera needs, and a shadow pass appends only the casters its light reaches. Shadow maps previously lost casters outside the main view under `reuse-main` and rewrote the main pass's list under `per-pass`. On WebGPU a nested pass issues one draw command per batch slot, so shadow-pass `gpuDraws` rise.
- Instance data, batch matrices, baked vertices and sprite centres are written in the scene's space, so a translated, rotated or scaled `Scene` no longer applies its transform twice; sprite batches swap their side while the scene is mirrored; `markDirty()` refits batch bounds and occlusion proxies, reaches detached originals and composes their matrices from the former parent; the batch sync rewrites every mover once the scene moved.
- Occlusion proxies issue no query when the camera is inside them, act only in the outermost render of the scene, stay quiet during `warmup()`, and are not built for a batch or instanced group holding a batch-synced mover (`report.occlusion.skippedSynced`).
- `exclusionRule` gains `invisible-ancestor`, `material-invisible`, `group-render-order` and `clipping-group`; `spriteRule` gains `sprite-node-material`, `sprite-count` and `sprite-custom-material`; `mirrored` is judged relative to the compile root, so meshes under a mirrored scene batch. `CompileReport.skipped` names the rule for each object.
- The bake takes a group only when its material is one of three's own classes with no instance function, no node in any slot and no `displacementMap`, and its geometry carries only `position`, `normal`, `tangent`, `uv`-`uv3` and a three-component `color`; every other group is batched and counted in `BakeSummary.unbakeableEntries`. A `normalLocal` node or a displacement map baked into scene space changed 4.40 % of the frame; an RGBA `COLOR_0` lost its alpha; a `colorNode = vertexColor()` group drew white.
- Seam pairs are removed only between closed, manifold, outward, front-side, opaque, non-casting shells from different entries whose islands cover their region once; shadow-casting statics keep their seam and buried faces; the buried pass considers only opaque, front-side, non-casting faces; duplicate copies go only when every copy draws the same and nothing else lies in their plane (two crates differing only by colour rendered in the hidden one's colour). `keptCoincidentFaces` and `keptDuplicateFaces` in `BakeReport`, `BakeSummary` and the CLI bake lines count what was kept. Tangents are carried and welded.
- Tinted batches, instanced groups and baked meshes keep the source material's instance functions, `defines`, `alphaTest`, user-added properties and shared `userData` (`cloneMaterial`); sprite batch materials copy every field of the sprites' material. A circular or BigInt `userData` no longer throws from `compile()`.
- The registry caches keys and hashes, treats a registered material as immutable (`invalidate`, `forget`, `dependentsOf`, `hashesOf`, `keysRevision`), keys `clippingPlanes` and user-added data, and counts a material once in `stats().registered`; `World.decompile()` and `ResourceTracker.release()` forget the materials they release and keep a canonical another material still resolves to.
- New `world.dispose()`; `decompile()` disposes only materials the World created; `bakeDebug()` returns copies; `warmup()` awaits `renderer.init()`, renders with `render()` and issues no occlusion query; a `compile()` that throws uninstalls its scene hooks so a retry does not double-install them; `freezableObjects` no longer freezes a container with no static leaf (`village` reports one more `autoUpdatedMatrices`).
- `AnimatedInstances` draws each part at its own offset from the character root. `Streamer` finds an object's chunk through an index (the same cost at 20 000 objects as at 2 000) and `dispose()` empties it. New `disposeLods(geometry)`. `RenderScheduler` stops once a `LoopOnce` clip finishes, keeps rendering through a fade, and sees a camera moved without `updateMatrixWorld()`. `DayNight.setTime()` rewrites the dome only when the palette changed.

#### CLI and MCP

- The parser is declarative: boolean flags no longer swallow the next argument (`analyze --json scene.glb` parses), `--` ends the flags, and every unknown, misplaced, repeated or malformed input exits 2 with a message naming the problem (`did you mean --json?`). The usage text and the `AGENTS.md` command and flag tables are generated from the specs. With `--json`, the document reaches stdout before the summary is built.
- `optimize --preset safe` is dedup, palette and prune, measured at 0 changed pixels on the Fox and the Buggy. Weld moves up to 0.014 % of the Fox's pixels on WebGPU; lossless resample grows Xbot by 1.248 % and the Fox by 0.100 %, while the lossy default saves Soldier 18.9 %, BrainStem 14.9 % and VirtualCity 9.5 %, so both steps live in `balanced` and `aggressive`. Under `safe`, `--resample` runs at `tolerance: 0`.
- `parity.views[]` carries `changedPixels` beside the rounded `diffPct`, `--parity 0` means zero changed pixels, renders of different sizes count as every pixel changed, and a failing reason names the count (`pixel parity 0.00% > 0% (3 changed pixels in the worst view)`). `optimize --parity` governs the two files as loaded; each file's own compile is judged at 0.5 %, which `analyze --parity` asks about directly.
- `analyze` and `optimize` refuse resource URIs that leave the input's directory, and the harness page can reach only the run's own static server; three's `GLTFLoader` would otherwise fetch an absolute `http://` URI from the developer's network. The server answers 403 for a symlink that resolves outside its root, 400 for a path it cannot decode, and never crashes on a request.
- Every page wait is bounded by `--timeout` (exit 4); a Chromium launch or `listen` failure exits 3 at once; the browser and server are closed on every path, each within 5 s, and a finished command exits at most 5 s after flushing its output. `window.__threeforge.frameAsync()` rejects when the render throws.
- A page error fails the `analyze` and `optimize` verdicts (exit 1), quoting up to five. The harness page disposes its PMREM generator, `RoomEnvironment` and loaders, so `analyze` documents lose a false `unreferenced-resources` hint (13 geometries, 4 textures, even for the Fox).
- Text read from an asset or page is cleaned before use: ANSI escapes, control characters, every Unicode format character, variation selectors and invisible fillers are stripped, strings are capped at 300 code points, non-finite numbers become 0, and arrays are capped at 256 entries with `compile.skippedCount` and `groupCount` giving the true lengths.
- The `analyze`, `inspect` and `optimize` documents are `schemaVersion: 2` with `-v2.json` ids; `threeforge schema`'s four schemas embed what they reference and validate standalone in ajv; the snapshot schema documents `items[].material` and the run-local stability of `programHash` and `variantHash`.
- The MCP server validates every input by the CLI's rules, drops `inspect_app`'s `tier`, confines `optimize_asset.out` and adds `overwrite`, returns a second content block marking output as data, annotates each tool (`optimize_asset` destructive, `inspect_app` open-world), and exits when stdin closes, aborting a running call through `CliDeps.signal`.
- `optimize`'s `requires[]` code for `KHR_texture_basisu` uses `detectSupport` after `await renderer.init()`, since `detectSupportAsync` is deprecated.

#### Bench

- The gate fails on a gated metric that is missing or not finite (`unattributed` included). `programs` counts the app's shaders, read before `measureOverdraw()`; `shadowTexels` is the mean over the 60 measured frames, so the optimized day/night scene reports half the naive value.
- Device results are ingested only after a maintainer applies `bench-accepted`; ingest checks the timestamp, recomputes the id, restricts env strings to printable ASCII (the bench page rewrites `®`, `™` and accents first), rejects bodies over 65,536 characters and never overwrites an existing id. `docs/devices.md` shows GPU and platform strings in code spans.
- The public asset corpus report is regenerated with run id `corpus-20260916`: 104 of 104 models pass on webgl2 and on webgpu (native Metal), with no table value changed. Every row records the commit and run that measured it, and the Markdown is rewritten only after a run over the whole index. `diff` is the changed-pixel percentage at a per-channel tolerance of 24, rounded to two decimals, so 0 means under 0.005 %; texture-heavy rows (`Sponza`, `polyhaven-CoffeeCart_01`) vary by up to 0.04 % between WebGPU regenerations, far under the 0.5 % gate.
- `scripts/fetch-assets.mjs` and `scripts/fetch-kits.mjs` confine every downloaded filename to its target directory and pin the Khronos sample URLs to commit SHAs.

#### Docs

- `exposeToAgents()` is shown guarded by `import.meta.env.DEV`, since the hook lets any script on the page compile the scene and read the ledger. `optimize --preset`'s description states what is measured (0 changed pixels on the Fox and the Buggy) rather than "never changes a pixel", `--parity` is described as governing the two files as loaded, and the bake guidance says to pass `analyze --parity 0`.
- `docs/threeforge.md` section 5 spells out the registry's immutability contract; `docs/bench.md` records each metric's measurement window; `docs/release.md` adds the corpus-report step.

## 0.8.0 (2026-09-14)

- `createLoader(renderer, options)`: a GLTFLoader with Draco, KTX2 (formats detected on the renderer) and meshopt in one call; `disposeLoader`; `threeforge decoders <dir>` copies three's decoder files.
- `ResourceTracker` (reference-counted release across owners, registry materials untouched), `collectResources`, `unreferencedResources`.
- `Streamer`: chunk residency by camera distance over `world.chunks()` and uncompiled static tiles; unloaded chunks free their GPU copies.
- Ledger: `memory.unreferenced` (renderer-held resources the scene no longer reaches), `memory.chunks`; budget `geometryBytes`; hints `geometry-bytes`, `unreferenced-resources`. Zen benchmark rebuilt on 64 textured ground tiles with fog and streamed in the optimized variant (baselines promoted). `docs/memory.md`.

## 0.7.0 (2026-09-14)

- `bakeAnimationTexture`: every clip of a skinned prototype baked to one float texture of bone matrices (multiple skeletons side by side), transform and pose restored.
- `AnimatedInstances`: crowds as one instanced draw per part with a per-instance clip, time offset and speed, animated on the GPU from the texture; instance matrices in one `InstancedInterleavedBuffer`.
- Ledger: reason `vat-instanced`, `skinning.vatInstances` / `vatVertices`; budget `bones`; hints `bones-over-budget`, `skinned-crowd`. Crowd benchmark optimized with animated instances (baselines promoted: 401 → 17 submissions, skinned vertices 271 k → 0). `docs/skinning.md`.

## 0.6.0 (2026-09-14)

- `DayNight`: sun, gradient sky dome, hemisphere light, fog and background from the hour of day; the shadow map re-renders only when the sun moved `everyDegrees`.
- `ShadowBudget`: shadow maps fitted to the tier's texel budget, point shadows off on phones, an off-switch by tier, `freeze(light)` for static shadows.
- Bake carries and welds every UV set (lightmaps survive). Bench metric `shadowPassesPerFrame` (baselines promoted: day/night 1 → 0.5).

## 0.5.0 (2026-09-14)

- Freezing at compile (`freeze`, default on): unbatched statics and all-static ancestors get `matrixAutoUpdate = false`; `world.markDirty(object)` moves a frozen static and updates its batch, instance or bake; `world.onDirty(listener)`.
- `RenderScheduler`: render on change (invalidate, camera, watched objects, mixers, resize, keep-alive) with `stats`, `lastReason` and `js.skipped` in the ledger.
- Ledger: `js.hiddenOriginals`, `js.skipped`; budget `objects`; hints `js-objects`, `detach-originals`; bench metrics `objects`, `autoUpdatedMatrices` (baselines promoted).

## 0.4.0 (2026-09-14)

- Sprite batching in `World.compile()`: sprites sharing a material become one instanced `SpriteNodeMaterial` draw synced from the originals every frame (`sprites`, `spriteThreshold` options; reason `sprite-batch`). Lake benchmark: 3 548 → 7 submissions.
- `ParticleBudget` (caps points and sprite batches to the tier's particle budget, scales point sizes) and `ResolutionScaler` (dynamic pixel ratio on the median frame time).
- Ledger: `overdraw.particles`, `overdraw.pixels`; budget `particles`; hints `particles-over-budget`, `sprites-unbatched`; bench metrics `particles`, `fillMegapixels`. `docs/vfx.md` conventions.
- Device bench page (`bench-app/`, deployed by the `pages` workflow): runs the eight benchmark scenes on any device, shows the `pnpm bench` metrics plus real frame times, and submits the result as a GitHub issue; the `bench-results` workflow validates it, stores it under `bench/devices/` and regenerates `docs/devices.md`. Not part of the npm package.

## 0.3.0 (2026-09-14)

- `threeforge optimize <file>`: glTF-Transform build-time pipeline with three presets (`safe` never changes a pixel; `balanced` adds quantize and WebP textures; `aggressive` adds simplify), per-step reports, load-time requirements (`requires`), verification by rendering the original and the optimized file through the harness and compiling both, and a verdict that fails on lost pixels, clips, skins or morph targets. `optimize_asset` on the MCP server, `schema optimize`, `optimizeAsset` in `threeforge/cli`.
- `@gltf-transform/{core,functions,extensions}` are dependencies; `sharp` (texture compression) and `draco3dgltf` (Draco inputs) are optional peers.

## 0.2.0 (2026-09-13)

- Ledger v2: six cost sections (draw calls, measured overdraw, skinning, lighting, js, memory), device tiers, budgets and hints.
- Benchmark suite: eight scenes with naive and optimized variants, `pnpm bench` regression gate, committed baselines.
- Bake: `World({ bake })` merges each finished static group into one mesh, removing seams and duplicates (and, opt-in, buried faces), welding matching vertices; rebake on hide, `bakeDebug()`, CLI `--bake --views N` multi-view parity.
- For AI agents: `npx threeforge analyze|inspect|explain|schema|mcp`, `exposeToAgents()` hook, `AGENTS.md`, `llms.txt`.
